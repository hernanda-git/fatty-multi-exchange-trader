## Rework: next steps, in order

1. **Protection-verification grace** — **done 2026-10-18**: bounded readback-retry
   (position + plans, ~5 attempts over 15 s, jittered) before containment; escalates only
   if still unconfirmed; the attempt trail rides the capability error and a
   `native-protection-verified-late` log line. Zero budget keeps library/test callers
   unchanged. Tests: confirmed-late never closes; unconfirmed still closes; zero-budget
   path untouched.
2. **Closed-lifecycle terminality** — **done 2026-10-18**: a filled entry whose position
   the venue proves flat *and* whose close fill is recorded settles itself at recovery
   (`recovery-closed-close-fill-verified`), and settled dispatches leave the candidate
   set. Flat without a recorded close stays unresolved on purpose: an unaccounted close
   must remain visible, so those dispatches (PUMP) still take an operator decision.
3. **Kernel slices 2+**: the same `park()` primitive for `console_jobs` and
   `dispatches`; then the "no absorbing state" property test that fails the build if a
   new non-terminal state can park without a deadline.
4. **Local stop trigger** (P0-3): the only local close trigger today is the 30 s REST
   poll, so widening the venue stop *now* would trade the 2.4 % signal stop for the
   ~4.5 % backstop in fast moves. Build the stream-driven close callback first, then
   widen the venue stop in the same release.
5. **Watchdog sweep** (workstream 2): stalled leases, canary exhaustion, stale fallback
   registrations (the PUMP/PENGU class retired by hand on 10‑18), and a second channel
   for delivery failures.
6. **Operator surface**: turn `scripts/requeue_late_signal.py`,
   `scripts/reconcile_unknown_intents.py` and the baseline flow into console actions,
   so nothing needs shell access.
7. Then workstreams 3–9 in `docs/MASTER-PLAN.md` (microstructure, execution quality,
   position intelligence, portfolio risk, signal scoreboard, replay harness).
